# ~/claude-projects/workspaces/README.md

What's a Claude Code project workspace?

A workspace is everything under a project's .claude/ directory plus its CLAUDE.md — the configuration that turns a generic Claude Code session into one that already knows your stack, your conventions, and the exact things it should never do.

# the pieces

A workspace is a composition of these — most projects use a handful, not all of them.

PieceWhat it's forLives at
MemoryStatic project facts and conventions Claude reads every session.CLAUDE.md
RulesPath-scoped instructions that only load when Claude touches matching files..claude/rules/*.md
SkillsReusable procedures — reference knowledge or a runnable task — invoked as /name or automatically..claude/skills/<name>/SKILL.md
CommandsFlat-file skills for simple, single-purpose slash commands..claude/commands/*.md
AgentsSubagents with their own model, tools, and system prompt — isolated context for a specific job..claude/agents/*.md
HooksShell commands (or HTTP/MCP/LLM calls) that fire on lifecycle events — format on save, block a risky edit, and so on..claude/settings.json (hooks key)
MCP serversConnections to external tools and data — issue trackers, databases, internal APIs..mcp.json
PluginsAny of the above, bundled and versioned for one-command install across projects./plugin install

# how they compose

Settings resolve across scopes — user (all your projects), project (checked in, shared with your team), and local (gitignored, just you) — with project and local layered on top of user. A workspace you commit to a repo is what every collaborator gets the moment they clone it and accept the workspace trust prompt; nothing needs installing beyond Claude Code itself.

Skills and rules only cost context when they're actually relevant — a rule scoped to src/auth/** never loads while you're editing the README. Hooks run deterministically regardless of what the model decides, which is why the one rule you can't afford to have forgotten (no edits on main) belongs in a hook, not a line in CLAUDE.md hoping the model remembers.

# see it end to end

examples/js-project-starter in the toolkit repo is a complete workspace wired against a real (small) app: memory, two skills, one subagent, one command, four hooks, an MCP config, and three GitHub Actions workflows, all cross-referenced so you can see exactly why each piece is there.
